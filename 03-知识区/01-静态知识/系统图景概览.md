# 系统图景概览

> 项目涉及的系统与链路，谁调谁，一眼看到。

## 一、投放与检索链路（广告计划如何被召回排序）

```
商家（万相台）
   └ 广告计划（预算/排期/出价/定向）
        ↓
加工层：Redis（实时存计划状态） + 倒排索引（query → 结果映射）
        ↓
LBS 召回（以可配送为主，半径放大）
        ↓
四通路并行召回：关键词召回 / 结构化召回 / 向量召回 / 协同召回
        ↓
粗排（双塔，截断）→ 精排（分页，算 eCPM）→ 重排/混排（品牌打散）
        ↓
与自然结果 PK → 呈现给用户
（CPT 另有一条素材召回通路，做千人千面）
```

## 二、品牌新力数据链路（本项目新增/改造）

```
站内行为日志（搜索/回店/浏览/加购/成交/复购）
   + 站外种草回流（对齐：来源、内容品牌、品牌对齐、用户对齐）
        ↓
语义大模型补全（5 类场景：内容与品牌词不一致 / 搜索词与内容不一致 /
                商品与主体不一致 / 链路中断补字段 / 模型自查置信度）
        ↓
规则判断（AI 只辅助识别，不决定是否计入品牌新力）
        ↓
归因去重 → 品牌新力指标（回搜 UV + 回购 UV/订单）
```

## 三、投后与商业化

```
品牌新力结果 → 投后报告（总览/趋势/解释）
              → 5 维拆解（内容/渠道/人群/关键词/商品系列）
              → 4 类诊断（高回搜高爆款 / 高回搜低爆款 / 低回搜高爆款 / 高曝光低回收）
              → 类目对标 → 预算承接（运营/销售对接品牌商）
```

## 四、横向

- **AB 实验平台**：以**用户搜索/回流请求**为对象，按用户/设备 ID 稳定分桶，指标落到 `request_id`。
- **万相台**：商家投放端，广告计划创建与出价。
