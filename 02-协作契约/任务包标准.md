# 任务包标准

每个任务在本人的个人仓 `02-任务/{任务名}/` 下开一个包，人人同构。任务名就是目录名，也是工作台条目和 `任务状态.yaml` 里的 task 字段。

## 五件套加一份状态

| 件 | 装什么 |
| --- | --- |
| `任务说明.md` | 目标一句话、上游协同单引用、验收标准、明确不做 |
| `输入清单.md` | 本任务允许读的文件逐条列路径。建包时查一次索引出候选，本人确认后定稿；清单外不读，要用先补清单 |
| `待裁决事项.md` | AI 拿不准、必须由人定的问题。新包初始是空表，空表本身也是信息 |
| `过程记录.md` | 追加式：日期、动作、结果、证据位置；失败也记，不删行 |
| `工作产出/` | 草稿与中间产物全在包内 |
| `任务状态.yaml` | 聚合地基，字段见下 |

## 待裁决两类

- 本人裁决：Owner 拍板即可，AI 停在这里等答案，得到答案后在原行补结论，不删行。
- 跨人裁决：结论在别人手里，走协同单投出去问，收到回执后在原行补结论，同时由统筹登记进 `00-推进管理/决策记录.md`。

## 任务状态.yaml

```yaml
task: 泛品牌词口径设计
from: 04-交换区/商业化产品（本人）/出件箱/20260901-商业化产品（本人）-算法AI团队（周衍）-泛品牌词识别口径-协同单.md
status: 进行中
blocked_by: 无
outputs:
  - 工作产出/泛品牌词口径-草稿V2.md
updated: 2026-09-01
```

- `from`：上游协同单路径，没有上游写「无」。
- `status` 枚举只有七个值，含义与进入条件见下表。
- `updated`：本人最后一次动这个包的日期。

## 七个状态的含义

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| 未开始 | 包已建，草稿未动笔 | 建包完成 |
| 进行中 | 草稿在写，或本人投出的单据在等对方 | 动笔，或协同单已投出 |
| 待本人确认 | 草稿写完，等本人确认升生效区 | AI 报草稿完成 |
| 已生效 | 本人确认，生效件在 `03-生效区/`，对外还没交 | 本人确认升版 |
| 已交回 | 回执已投给上游单的发起人 | `send_receipt.py` 跑完 |
| 已完成 | 有上游单：发起人验收通过并归集；无上游单：对方回执收到、本人收口 | 归集件出现在 `归集产出/current/`，或收到回执后本人定 |
| 阻塞 | 等跨人裁决或外部依赖 | 登记跨人裁决或依赖，`blocked_by` 写原因 |

正常走向：未开始、进行中、待本人确认、已生效、已交回、已完成，逐级向后。无上游单的任务从已生效直接到已完成。任何状态都可以进阻塞，解除后回到进入阻塞前的状态。

## 收工三件套，进度自己走

每次收工做三件事：更新 `任务状态.yaml`、追加 `过程记录.md`、写 `09-工作日志/{日期}.md`，然后提交并推送。

进度不用人搬：个人仓（本仓，独立 git 仓）的 `post-commit` hook 看到本次提交动了 `任务状态.yaml`，就跑公共区 `88-工具箱/脚本/sync_desk.py`，把本人工作台从全部任务包的 yaml 重新生成、**以本人身份**提交并推送公共区；公共区推送后远端 `post-receive` hook 再重建任务看板、三本索引与通知台账。**yaml 是进度链上唯一的结构化来源**：工作台是它的**纯投影**；看板读四类输入（项目目标、当前推进、全员工作台、交换区与归集产出）做**汇总与对账**，索引与通知台账也另由脚本生成——这几样谁都不手改。yaml 本身由本人（或其 AI）在收工时改写，脚本只读不写。hook 没装或没跑起来，手动跑同一条 `sync_desk.py` 命令。

## 草稿到生效

草稿留在任务包 `工作产出/`，本人确认后才升入个人仓 `03-生效区/`；替换已有生效件之前，旧版先原样移入 `04-归档区/`。
